# 开放问题

## 性能

### 大文件夹性能

**问题**：包含数百万文件的文件夹性能下降。

**现状**：
- 数据库查询随文件数增长变慢
- 扫描时间长
- 内存使用高

**可能方向**：
- 数据库分片
- 增量扫描优化
- 内存映射文件

### 加密文件夹开销

**问题**：加密文件夹的 CPU 和存储开销。

**现状**：
- 每文件独立密钥派生
- AES-SIV 确定性加密
- 块填充防大小泄露

**可能方向**：
- 硬件加速
- 减少填充开销
- 批量密钥派生

## 协议

### BEP 版本协商

**问题**：当前协议版本协商有限。

**现状**：
- Hello 消息包含版本
- 未知消息类型跳过
- 无正式的能力协商

**可能方向**：
- 正式的能力协商机制
- 版本兼容性矩阵

### 大块支持

**问题**：大文件块大小选择。

**现状**：
- 默认 128KB
- 大块模式动态调整
- 每文件独立块大小

**可能方向**：
- 自适应块大小
- 基于网络条件调整

## 数据库

### Schema 迁移

**问题**：Schema 迁移的复杂性。

**现状**：
- 6 个迁移版本
- 迁移不可逆
- 需要停机迁移

**可能方向**：
- 在线迁移
- 双写迁移
- 可逆迁移

### 跨 folder 查询

**问题**：Per-folder 数据库不支持跨 folder 查询。

**现状**：
- 每个 folder 独立数据库
- 跨 folder 查询需要聚合

**可能方向**：
- 全局索引
- 物化视图

## 安全

### 不可信设备的大小泄露

**问题**：加密文件夹仍泄露文件数量和大小模式。

**现状**：
- 块填充到 1024 字节
- 固定时间戳和权限
- symlink 用 Directory 表示

**可能方向**：
- 更大的填充
- 块大小混淆
- 假文件

### 设备 ID 信任模型

**问题**：设备 ID 通过带外渠道交换，可能被篡改。

**现状**：
- 手动输入或二维码
- 无 PKI/CA

**可能方向**：
- 可选的 CA 支持
- Web of Trust
- 二维码签名验证

## 用户体验

### 冲突解决

**问题**：冲突文件需要用户手动处理。

**现状**：
- 生成 `.sync-conflict-*` 文件
- 用户手动合并

**可能方向**：
- 自动合并策略
- 冲突解决 UI
- 三方合并工具

### 移动平台

**问题**：移动平台资源限制。

**现状**：
- 电池消耗
- 后台限制
- 存储限制

**可能方向**：
- 适配移动平台的同步策略
- 增量同步优化
- 后台任务优化

## 可维护性

### 旧数据库代码

**问题**：`internal/db/olddb/` 仅用于迁移，增加维护负担。

**现状**：
- LevelDB 实现
- 迁移代码
- 不可用于新数据

**可能方向**：
- 迁移完成后移除
- 独立迁移工具

### Web UI 现代化

**问题**：Web UI 基于传统技术栈。

**现状**：
- 原生 JavaScript
- 手动 DOM 操作

**可能方向**：
- 框架迁移（React/Vue）
- 组件化
- 类型安全
